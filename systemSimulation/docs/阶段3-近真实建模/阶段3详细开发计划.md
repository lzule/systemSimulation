## 1. 本阶段要解决什么

当前系统虽然具备双轴几何与控制底座（阶段 2 产出），但成像、检测、控制器输入都过于理想：

- 目标大小固定（σ=3.2px），不随距离变化
- 目标亮度固定（blob × 255），无大气衰减或反射率变化
- 检测永远成功（只要有像素偏差就找得到），无丢检
- 控制器可读取全部 target 真值（x, y, z, vx, vy, bearing, distance），存在观测泄漏
- 无 obs_filter 机制，无法按模式分离输入

本阶段的核心目标是：**让平台具备研究算法鲁棒性的能力**。具体包括两轮交付：

- **轮 A（优先）**：感知真实性 + 控制器输入模式分离
- **轮 B（后续）**：执行器真实性 + 延时策略扩展

---

## 2. 本阶段不做什么

1. 不实现 ATP 状态机（捕获/粗跟踪/精跟踪/失锁恢复）— 阶段 4
2. 不增加通信链路仿真 — 下一轮
3. 不增加多目标/杂波（轮 B 可选项，本轮 A 不做）

5. 不替换现有成像模型为物理光线追踪 — 只在当前高斯亮点模型上扩展参数

## 4. 轮 A 任务拆分

### 任务 A1：扩展目标成像模型

**目标**：让成像模型支持距离相关大小、亮度变化、偶发丢检三项近真实因素。

**具体动作**：

1. **距离相关 sigma**（`entities/camera/model.py`）：
   - 当前：`sigma = self.cfg.beacon_sigma_px`（固定 3.2px）
   - 改为：`sigma = sigma_base / (1 + distance_m / sigma_ref_distance_m)`
   - 其中 `sigma_base` 为基准 sigma（默认保持 3.2px），`sigma_ref_distance_m` 为参考距离（默认 100m）
   - 距离越远 → sigma 越小 → 目标越暗淡越难检测
   - 当 `sigma_ref_distance_m = 0` 时退化为固定 sigma（保持向后兼容）
   - `render_beacon_frame()` 需要接收 `distance_m` 参数

2. **亮度变化**（`entities/camera/model.py`）：
   - 当前：`blob * 255.0`（固定最大亮度）
   - 改为：引入亮度衰减因子 `brightness = base_brightness / (1 + distance_m / brightness_ref_distance_m) + np.random.normal(0, brightness_jitter_std)`
   - 新增参数：`brightness_base`（默认 1.0）、`brightness_ref_distance_m`（默认 200m）、`brightness_jitter_std`（默认 0.0，关闭）
   - 亮度值 clip 到 [0, 1]，然后乘以 255
   - 当 `brightness_ref_distance_m = 0` 且 `brightness_jitter_std = 0` 时退化为固定亮度

3. **偶发丢检**（`entities/camera/model.py`）：
   - 不在 `camera` 层伪造 `Detection` 对象；丢检应体现在**输出帧无法被检测器检出**，避免职责混乱
   - 推荐做法：在目标已进入 FOV 且像素坐标在画面内时，按概率决定本帧是否”掉点”；若掉点，则**跳过 blob 渲染**
   - 为避免把“漏检模拟”误做成“随机误检”，丢检帧应输出**背景帧**：黑底或严格受控的低幅噪声，保证像素不会越过当前检测阈值；本阶段不借机引入误警/杂波，误警留到后续更高阶段处理
   - 丢检概率必须满足”sigma 越小，越容易丢检”的单调关系（sigma 小 = 目标远/暗淡 = 更难检出）
   - 公式：`miss_rate = clip(miss_detection_base_rate + miss_sigma_gain_px / max(sigma_px, eps), 0, 1)`
   - 当 `miss_detection_base_rate = 0` 且 `miss_sigma_gain_px = 0` 时退化为永不丢检
   - 丢检时 `camera_state.in_fov` 保持为 `True`（几何上目标仍在视场内），`u_px`/`v_px` 正常计算（反映真实投影位置），仅图像不含目标亮斑

4. **配置集中**（`config.py`）：
   - `CameraConfig` 新增字段（这些参数属于成像链路，不应放进 `SceneConfig`）：
      ```python
      # 距离相关 sigma
      sigma_ref_distance_m: float = 0.0        # 0 = 固定 sigma（向后兼容）
     # 亮度变化
     brightness_base: float = 1.0
      brightness_ref_distance_m: float = 0.0   # 0 = 固定亮度（向后兼容）
      brightness_jitter_std: float = 0.0        # 0 = 无抖动
      # 丢检
      miss_detection_base_rate: float = 0.0     # 0 = 永不丢检（向后兼容）
      miss_sigma_gain_px: float = 0.0           # 0 = 永不丢检
      ```
   - 所有新参数默认值确保**完全向后兼容**：当前所有测试在默认参数下行为不变

**涉及文件**：`entities/camera/model.py`、`entities/camera/entity.py`、`config.py`
**改动范围**：中
**前置依赖**：无

### 任务 A2：实现控制器输入模式分离（obs_filter）

**目标**：根据阶段 1 冻结的三种观测模式定义，实现 obs_filter 层，使控制器在不同模式下只能访问对应白名单内的字段。

**具体动作**：

1. **新建 `simulation/obs_filter.py`**：
   - 定义 `ObsFilter` 类，接受 `mode` 参数（`"debug"` / `"research"` / `"realistic"`）
   - `filter_obs(world_obs: dict) -> dict` 方法：
     - `"debug"` 模式：透传全部 obs（当前行为，零改动）
     - `"research"` 模式：只保留白名单字段
       - `timestamp`
       - `gimbal.mode`（ANGLE_MODE / RATE_MODE）
       - `camera.f_current_mm`
       - `frame.image`
       - `frame.intrinsics`（cx, cy, f_px, f_mm, width, height）
      - `"realistic"` 模式：frame.image + 有噪声的 gimbal 测量值 + 无 target
        - `timestamp`
        - `gimbal.mode`
        - `gimbal.yaw_deg_internal`（取自 gimbal `get_measured_state()` 的量化值，再叠加 `N(0, encoder_noise_std_deg)`）
        - `gimbal.pitch_deg`（同上）
       - `gimbal.yaw_rate_dps + N(0, gyro_noise_std_dps)`
       - `gimbal.pitch_rate_dps + N(0, gyro_noise_std_dps)`
       - `camera.f_current_mm`
       - `frame.image`
       - `frame.intrinsics`
    - `realistic` 模式的噪声参数从 config 读取
    - 注意：如果 `ObsFilter.filter_obs()` 只接收普通 `world_obs: dict`，它本身**无法凭空拿到** `get_measured_state()`；因此实现时必须二选一：
      - 方案 A：由 runtime 在构建观测时额外生成 `gimbal_measured` 并传给 obs_filter
      - 方案 B：让 obs_filter 在运行时持有 gimbal 实体引用并显式调用 `get_measured_state()`
    - 推荐方案 A：保持 obs_filter 仍是“纯观测整形层”，不要让它反向依赖实体对象

2. **集成到运行时**（`runtime/digital_twin_runtime.py`）：
    - `DigitalTwinRuntime.__init__()` 接受 `obs_mode` 参数
    - 在 `step()` 中构建 `world_obs` 后，调用 `obs_filter.filter_obs(world_obs)` 再传给 raspi
    - 若采用推荐方案 A，则在这里同时构造 `gimbal_measured_state` 并一并交给 obs_filter
    - 默认 `obs_mode = "debug"`（向后兼容）

3. **集成到 bootstrap**（`simulation/bootstrap.py`）：
   - `build_runtime()` 接受 `obs_mode` 参数并传给 `DigitalTwinRuntime`

4. **CLI 集成**（`simulation/cli.py` + `simulation/types.py`）：
   - `AppConfig` 增加 `obs_mode: str = "debug"` 字段
   - CLI 增加 `--obs-mode` 参数，支持 `debug` / `research` / `realistic`
   - 传递到 bootstrap

5. **配置集中**（`config.py`）：
   - 新增独立配置块（建议 `ObsConfig` 或同等语义名称），避免把观测过滤参数混进 `SceneConfig`
      ```python
      obs_mode: str = "debug"                  # 默认调试模式（向后兼容）
      encoder_noise_std_deg: float = 0.0       # 编码器噪声标准差（realistic 模式用）
      gyro_noise_std_dps: float = 0.0          # 陀螺仪噪声标准差（realistic 模式用）
      ```
   - `obs_mode` 既要能被 CLI 覆盖，也要保留配置默认值，便于脚本和 GUI 统一复用

**涉及文件**：新建 `simulation/obs_filter.py`，修改 `runtime/digital_twin_runtime.py`、`simulation/bootstrap.py`、`simulation/cli.py`、`simulation/types.py`、`config.py`
**改动范围**：中
**前置依赖**：无（与 A1 独立）

## 5. 轮 B 任务拆分（轮 A 完成后执行）

### 任务 B1：扩展云台非理想项

**目标**：为云台添加编码器量化噪声、静摩擦/死区、参数偏差三项非理想行为。

**具体动作**：

1. **编码器量化噪声**（`entities/gimbal/entity.py`）：
   - 在**可观测输出路径**上引入量化，不直接污染内部连续状态
   - 新增 `get_measured_state()` 方法，返回量化后的角度值（yaw_deg_internal、pitch_deg）
   - `get_state()` 保持返回内部连续值不变（debug 模式和内部控制器使用）
   - obs_filter 的 realistic 模式应从 `get_measured_state()` 读取量化值，再叠加随机噪声；debug 模式继续用 `get_state()` 读取原始值
   - `quantized = round(angle / encoder_resolution_deg) * encoder_resolution_deg`
   - 新增配置：`encoder_resolution_deg`（默认 0.0 = 无量化，`get_measured_state()` 退化为返回原始值）
   - 这样 debug 模式永远看到连续值，research 模式不读 gimbal 角度（白名单不含），realistic 模式看到量化+噪声，三种模式各司其职不互相干扰

2. **静摩擦/死区**（`entities/gimbal/model.py`）：
   - 在 `_first_order_rate_update()` 中，当 |rate_cmd| < static_friction_threshold_dps 时，rate 输出为 0
   - 新增配置：`static_friction_threshold_dps`（默认 0.0 = 无死区，向后兼容）

3. **参数偏差**（`entities/gimbal/model.py`）：
   - 在 `__init__()` 中，对 `response_tau_s` 添加随机偏差：`tau_actual = tau_nominal * (1 + N(0, tau_deviation_ratio))`
   - 新增配置：`tau_deviation_ratio`（默认 0.0 = 无偏差，向后兼容）
   - 偏差在初始化时确定，运行过程中保持不变

**涉及文件**：`entities/gimbal/model.py`、`entities/gimbal/entity.py`、`config.py`
**改动范围**：中
**前置依赖**：轮 A 完成

### 任务 B2：扩展延时模型选项

**目标**：在单槽抓最新帧之外，增加有限队列模式和多速率选项。

**具体动作**：

1. **有限队列模式**（`entities/raspi/model.py`）：
   - 当前 RaspiDelayModel 是单槽（新帧到来时丢弃旧帧）
   - 建议显式区分“缓存策略”和“缓存容量”，避免只有 `queue_capacity` 却说不清抓最新还是 FIFO
   - 例如：`buffer_policy = "latest"`（当前行为） / `"fifo"`（有限队列），`queue_capacity` 决定容量
   - `queue_capacity=1 + buffer_policy="latest"` 必须严格等价于当前行为
   - 通过 `RaspiDelayConfig` 配置

2. **多速率采样**（`entities/raspi/entity.py`）：
   - 当前每个 tick 都尝试处理
   - 新增 `control_rate_hz`：控制程序调用频率
   - 在 `update()` 中只在控制 tick 到来时才调用 control_program
   - 默认值建议明确写成 `0.0 = 每 tick`，因为当前行为由 runtime `dt_s` 决定，而不是写死 200Hz

3. **配置集中**（`config.py`）：
   - `RaspiDelayConfig` 新增：
      ```python
      buffer_policy: str = "latest"         # latest=当前单槽抓最新，fifo=有限队列
      queue_capacity: int = 1               # 1 + latest = 当前行为；fifo 时表示缓冲容量
      control_rate_hz: float = 0.0          # 0=每tick（向后兼容），>0=指定频率
      ```

## 7. 风险点与控制方式

### 风险 1：近真实参数默认值导致旧测试失败

**控制**：所有新参数默认值保证"零效果"：
- `sigma_ref_distance_m = 0` → 固定 sigma
- `brightness_ref_distance_m = 0` → 固定亮度
- `miss_detection_base_rate = 0` → 永不丢检
- `miss_sigma_gain_px = 0` → 永不丢检
- `obs_mode = "debug"` → 透传全部 obs
- `encoder_resolution_deg = 0` → 无量化
- `static_friction_threshold_dps = 0` → 无死区
- `tau_deviation_ratio = 0` → 无偏差

### 风险 2：obs_filter 过滤过度导致控制程序无法运行

**控制**：
- BaselineTrackerProgram 只使用 frame + gimbal.mode，在 research 模式下可正常运行
- 先在 research 模式下跑 e2e 验证基线控制器可用性
- realistic 模式下添加噪声可能导致性能下降，但不应崩溃

### 风险 3：render_beacon_frame 签名变更破坏测试

**控制**：
- `render_beacon_frame` 增加 `distance_m` 参数，默认值 `0.0`
- 当 `distance_m = 0` 且 `sigma_ref_distance_m = 0` 时，sigma 不变
- 阶段 2 的 11 个调用点中已有 beta_rad 默认，增加 distance_m 时同样给默认值

### 风险 4：丢检概率参数脱离实际

**控制**：
- 丢检概率设计为**可配置**的连续函数，不做硬编码
- 初始参数值参考阶段 0 基线（sigma=3.2, 距离~100m）设定
- 丢检实现要落在“图像可见性/可检测性”层，而不是伪造检测器输出，避免把相机和检测器职责搅在一起
- 通过 e2e 实验验证：在基线距离下丢检率 < 5%，在远距离（500m+）下丢检率显著上升

### 风险 5：随机性引入导致测试不稳定

**控制**：
- 所有随机过程支持 seed 控制
- e2e 测试中固定 seed，确保可复现
- 单元测试中测试统计特性（均值/方差），不做精确值断言
- 丢检背景帧若带噪声，噪声幅值必须被约束在检测阈值以下，避免测试在“漏检”和“误检”之间随机摆动
