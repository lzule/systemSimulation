# 角度曲线实验方案

> 独立实验说明  
> 目标：在不改当前仓库代码、不污染当前工作目录的前提下，额外画出“目标角度 / 云台角度 / 误差角度”曲线。

## 1. 目的

这次实验只回答一件事：当前系统能不能稳定画出类似下面的曲线，并且图的含义是对的。

- 目标角度
- 云台角度
- 误差角度

首版先做 `pitch`，通过后再补 `yaw`。

## 2. 结论

可以做。

当前系统已经有足够的数据链路：

- 图像帧
- 相机内参
- 云台角度
- 延时后的“控制器真正收到的那一拍观测”

所以这类曲线可以从现有系统旁路导出，不必改主工程逻辑。

## 3. 本次边界

本次实验必须满足以下约束：

- 不修改仓库代码
- 不写入当前工作目录
- 不更新 `CHANGELOG.md`
- 不影响现有 GUI、CLI 和测试流程
- 所有临时文件只放到 `S:\tmp\angle_curve_experiment\`

## 4. 曲线口径

首版只定义单轴，推荐用 `pitch`：

| 名称 | 含义 |
|---|---|
| `imu_pitch` | 控制器收到这帧观测时，观测包里的云台 pitch 角 |
| `cam_target_pitch` | 根据这帧图像中的目标位置，反推出的目标 pitch 角 |
| `err_pitch` | `cam_target_pitch - imu_pitch` |

说明：

- 这里的“IMU 角度”按系统当前可见的云台测量角来理解。
- 目标未检出时，不强行补值，记为 `NaN`，曲线断开更直观。
- 如果后续要看 `yaw`，完全可以同样方式再画一张。

## 5. 推荐数据源

优先使用“控制器实际收到的观测包”，而不是简单拿当前快照后处理。

原因很简单：

- 你要的是“识别前那一拍”
- 这就要求图像和云台角必须来自同一个观测包
- 否则图会画出来，但含义会偏

建议采用下面这条链路：

```text
现有仿真
  ↓
外置临时脚本
  ↓
观测代理层（只记录，不改逻辑）
  ↓
控制器收到的那一帧图像 + 云台角
  ↓
反算目标角
  ↓
画曲线
```

## 6. 推荐实验模式

首版推荐：

- `obs_mode = realistic`
- 离线仿真
- 目标运动用当前已有的默认运动
- 只先做 `pitch`

原因：

- 更接近真实观测
- 更符合“识别前那一拍”的含义
- 结果更适合看延时和误差关系

## 7. 输出目录

建议统一放到：

```text
S:\tmp\angle_curve_experiment\<timestamp>\
```

建议产物：

- `raw_samples.csv`
- `pitch_curve.png`
- `summary.txt`

可选补充：

- `yaw_curve.png`

## 8. 图形建议

推荐画成上下两块：

```text
上图：imu_pitch + cam_target_pitch
下图：err_pitch
```

这样误差变化最容易看，不会和主曲线挤在一起。

## 9. 样本字段

`raw_samples.csv` 建议至少包含：

- `sample_idx`
- `obs_ts`
- `imu_pitch_deg`
- `cam_target_pitch_deg`
- `err_pitch_deg`
- `detected`
- `u_px`
- `v_px`
- `cx_px`
- `cy_px`

如果后面需要，也可以顺手加上：

- `distance_m`
- `sigma_px`
- `brightness`

## 10. 实施方式

建议用一个外置临时脚本完成：

- 只 import 现有仓库模块
- 只做代理记录和画图
- 不回写主工程
- 不改任何现有配置文件

如果需要严格对齐“控制器真正看到的那一帧”，就把控制程序包一层代理，让它在 `on_tick()` 入口处记录观测。

## 11. 风险点

| 风险 | 说明 | 处理 |
|---|---|---|
| 图像和云台角不同步 | 口径会变脏 | 只记录同一观测包 |
| 目标丢失 | 曲线出现空段 | 这是正常现象，保留空段 |
| 直接用快照后处理 | 可能不是“识别前那一拍” | 不作为首版方案 |
| 结果文件落到主目录 | 影响当前工作 | 只写 `S:\tmp` |

## 12. 验收标准

满足以下条件即可认为首版完成：

- 能生成 `pitch_curve.png`
- 曲线口径解释得清楚
- 样本数据能追溯
- 没有改坏当前仓库
- 没有污染当前工作目录

## 13. 使用轨迹预测算法后的扩展方案

### 13.1 适用范围

如果后续实验切到“带预测器”的路径，本方案也可以直接扩展。

当前系统里已经有预测器接口，至少包括：

- Alpha-Beta 预测
- 线性 Kalman 预测

它们的共同特点是：

- 输入仍然是控制器真正收到的观测
- 输出不是世界真值，而是“未来若干步的图像平面预测位置”
- 跟踪器会把这个预测位置当作新的参考点来生成控制量

### 13.2 先区分两类图

用了预测以后，不能只是在原来三条线里再硬塞一条线。

更合理的做法是分成两类图：

1. 控制用曲线  
看“控制器此刻依据什么在打舵”

2. 预测效果评估曲线  
看“预测本身到底准不准”

这两类图的含义不同，不能混为一谈。

### 13.3 控制用曲线怎么画

如果启用预测器，`pitch` 建议画成两层：

上图：

- `imu_pitch`
- `cam_target_pitch`
- `pred_target_pitch`

下图：

- `obs_err_pitch = cam_target_pitch - imu_pitch`
- `pred_err_pitch = pred_target_pitch - imu_pitch`

这里各条线的含义是：

| 名称 | 含义 |
|---|---|
| `imu_pitch` | 当前观测包里的云台 pitch |
| `cam_target_pitch` | 当前图像实际观测到的目标 pitch |
| `pred_target_pitch` | 预测器给出的未来目标 pitch |
| `obs_err_pitch` | 当前观测误差 |
| `pred_err_pitch` | 预测参考点相对当前云台的误差 |

### 13.4 预测效果评估曲线怎么画

如果要评估预测器是否真的有效，建议另画一张图，不和控制图混在一起。

推荐画法：

上图：

- `pred_target_pitch(t)`
- `future_actual_pitch(t + Δ)`

下图：

- `pred_true_err_pitch = future_actual_pitch(t + Δ) - pred_target_pitch(t)`

这里的重点是：

- `pred_target_pitch(t)` 是时刻 `t` 给出的预测
- 它不应该拿去和同一时刻的实际观测比
- 它应该去和“预测地平线之后”的实际观测比

否则评估结果会失真。

### 13.5 预测角度的来源

当前预测器输出的是图像平面位置，不是直接输出角度。

所以需要先把预测像素位置反算成角度，再画曲线。

对 `pitch`，建议统一按下面这个口径处理：

- 已观测目标角：由当前检测到的 `v_px` 反算
- 预测目标角：由预测器给出的 `pred_v_px` 反算

也就是说：

- `cam_target_pitch` 来自当前检测点
- `pred_target_pitch` 来自预测点

这样两条线才能放在同一张角度图里比较。

### 13.6 预测实验推荐输出

启用预测器后，建议比基础版多输出这些文件：

- `pitch_curve_with_prediction.png`
- `prediction_quality_pitch.png`
- `predictor_samples.csv`

`predictor_samples.csv` 建议增加这些字段：

- `predictor_name`
- `predict_steps`
- `pred_u_px`
- `pred_v_px`
- `pred_target_pitch_deg`
- `pred_horizon_s`
- `future_actual_pitch_deg`
- `pred_true_err_pitch_deg`

### 13.7 推荐对比方式

如果要判断“预测到底有没有帮助”，建议按完全相同场景跑两组：

- A 组：不启用预测器
- B 组：启用预测器

保持这些条件一致：

- 相同目标运动
- 相同延时配置
- 相同仿真时长
- 相同控制程序主体

这样才能把差异主要归因到“是否使用预测”。

### 13.8 需要特别注意的地方

- 预测器输出的是“未来参考点”，不是目标真值，不能和世界真值直接混画成一条“同义曲线”。
- 预测器在短时丢目标后，可能仍会继续外推，这时预测曲线继续而观测曲线中断，属于正常现象。
- 评估预测准确性时，必须和未来时刻的实际观测对齐，不能和当前观测直接比。
- 如果后续同时做 `yaw`，建议保持与 `pitch` 完全一致的命名和画法，不要换口径。

## 14. 结论

这是一项适合单独做的额外实验。  
先做 `pitch` 的严格版最稳，确认口径没问题后，再补 `yaw` 和更细的分析图。  
如果后续接入轨迹预测算法，建议把“控制用曲线”和“预测效果评估曲线”分开输出，这样图的含义才不会混乱。
