## 二、v2 本身的小建议（不阻塞实施）

### 建议1：详细计划 7.2 中 `run_benchmark.py` 的改动描述可以再收窄

详细计划 7.2 第 1 条写的是：

> `tools/run_benchmark.py` — 实验批次注释支持 + 视任务 A2 需要补充向后兼容记录字段

而 4.2 第 7 条已经说了"不在阶段5中引入 benchmark 主链路侵入式优化"。这两条放在一起容易让执行者拿不准"实验批次注释支持"到底算不算侵入主链路。

**建议**：执行时明确——`--experiment-note` 只是给 `run_benchmark.py` 加一个可选参数，往 result.json 里多写一个字段，不改动运行逻辑。如果觉得这个改动有侵入风险，也可以把记录骨架生成做成独立的 `tools/generate_experiment_log.py`，不碰 benchmark 本体。

这个在执行时决定即可，不需要改文档。

### 建议2：数据盘点不需要单独产出正式文档

详细计划 6.0 已经写了"不要求单独形成正式长文档"。这个判断是对的。

**补充建议**：数据盘点的结论可以直接以对话中的文字记录或一份简单的 Markdown note 形式保存在阶段5目录下（如 `docs/阶段5-研究支撑与结果固化/data_inventory.md`），方便后续执行时回查。不需要格式精美，只要能回答"哪些数据可用、哪些需要补充"即可。

### 建议3：闸门中"至少一种跨算法对比图"的优先级与 P2 的定位略有不一致

详细计划闸门第 5 条：

> 至少一种跨算法对比图可稳定生成

但对比可视化在优先级表中是 P2（选做）。如果它出现在闸门中，就意味着不做完对比图就不能收尾阶段5，这等于把 P2 变成了 P0。

**建议**：执行时如果对比图确实来不及做，可以从闸门中移除这一条，不影响阶段5的核心交付。或者现在就把这一条从闸门移到"P2 完成时的附加检查"。
