## 1. 平台是什么

云台数字孪生仿真系统是一个基于 Python 的云台-相机-目标跟踪闭环仿真平台，含树莓派控制器。系统由四个核心实体组成，由 `DigitalTwinRuntime` 按固定 tick 顺序调度：

```
Target ──── target_state (x_m, y_m, z_m) ────┐
                                             v
Gimbal ─── gimbal_state (yaw, pitch) ──────> Camera ── frame + world_obs ──> Raspi
   ^                                                                   │
   └──────────── Command (set_rate_target, set_mode) ──────────────────┘
                     通过 Runtime 命令总线
```

- **Target**：目标运动体，支持 5 种运动类型（正弦、匀速、匀加速、随机游走、航点），输出世界坐标 `(x, y, z)`
- **Gimbal**：两轴云台，执行 yaw/pitch 角速度或角度控制，输出姿态
- **Camera**：挂载在云台上的相机，根据目标方位和云台姿态成像（双轴针孔模型）
- **Raspi**：树莓派控制器，从帧中检测目标，运行控制程序，输出控制命令

调度顺序：`收命令 → Target → Gimbal → Camera → Raspi → 发布快照`，每 tick 严格按此顺序执行。

### 单 tick 数据流

```
_apply_due_commands()
  → Target.update()          # 目标按运动模式推进位置
  → Gimbal.update()          # 云台执行命令、推进姿态
  → Camera.update()          # 相机成像、计算像素位置
  → Raspi.update(world_obs)  # 控制器收到观测、运行控制程序、发出命令
  → WorldSnapshot            # 发布当前 tick 全局快照
        ↑                          │
        └──── Command (延时后) ────┘
```

Raspi 命令经延时管线（IDLE → READING → PROCESSING → SENDING → IDLE）延迟后，在下一个 tick 的 `_apply_due_commands()` 中生效。命令仲裁采用 latest-wins；未 READY 设备的命令被拒绝。

## 3. 快速启动

### 环境准备

```bash
conda activate simulation   # 激活 conda 环境
cd systemSimulation         # 进入项目目录
```

```bash
conda run -n simulation python app.py --no-gui --mode offline --duration 1.0
```

成功判据：出现 `t=... yaw=... u=... in_fov=...` 周期输出，无异常堆栈。

### GUI 实时仿真

```bash
conda run -n simulation python app.py --mode realtime --duration 60
```

## 4. 常见运行方式

### 4.1 运行参数速查

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `--duration` | float | 60.0 | 运行时长（秒） |
| `--mode` | realtime/offline | realtime | 运行模式 |
| `--delay-ms` | float | 0.0 | Raspi 链路延时（毫秒） |
| `--no-gui` | flag | False | 无窗口模式 |
| `--control-program` | str | "" | 自定义控制程序 `module:Class` |
| `--target-type` | str | "" | 运动类型：sinusoidal/constant_velocity/constant_accel/random_walk/waypoint |
| `--waypoints` | str | "" | 航点轨迹 `"(x,y,z,s),(...)"` |
| `--obs-mode` | debug/research/realistic | debug | 观测过滤模式 |

### 4.2 无 GUI 离线仿真

```bash
# 基础离线运行
conda run -n simulation python app.py --no-gui --mode offline --duration 5.0
```

### 4.3 带延时仿真

```bash
# 20ms 链路延时
conda run -n simulation python app.py --no-gui --mode offline --duration 5 --delay-ms 20
```

延时越大，控制程序看到的观测越陈旧，跟踪性能越差。推荐调参顺序：
1. 0 延时跑通闭环
2. 固定目标速度，观察像素误差收敛
3. 逐步叠加延时（5ms → 10ms → 20ms → 50ms）

### 4.4 自定义控制程序

```bash
# 加载自己的控制程序
conda run -n simulation python app.py --no-gui --control-program my_tracker:MyTracker --duration 10
```

控制程序必须实现 `on_tick(obs: dict) -> list[Command]` 协议。详见[树莓派控制程序开发手册](树莓派控制程序开发手册.md)。

### 4.5 不同运动模式

```bash
# 匀速直线
conda run -n simulation python app.py --no-gui --target-type constant_velocity --duration 5

# 随机游走
conda run -n simulation python app.py --no-gui --target-type random_walk --duration 10

# 航点轨迹（3D）
conda run -n simulation python app.py --no-gui --waypoints "(100,0,20,2),(80,30,10,1.5),(60,0,0,0)" --duration 20
```

支持 5 种运动类型：`sinusoidal`（正弦）、`constant_velocity`（匀速）、`constant_accel`（匀加速）、`random_walk`（随机游走）、`waypoint`（航点）。

### 4.6 观测模式

```bash
# debug 模式：全量信息（含目标真值）
conda run -n simulation python app.py --no-gui --obs-mode debug --duration 5

# research 模式：不含目标真值（研究推荐）
conda run -n simulation python app.py --no-gui --obs-mode research --duration 5

# realistic 模式：近真实传感器噪声
conda run -n simulation python app.py --no-gui --obs-mode realistic --duration 5
```

### 4.7 组合场景示例

```bash
# 延时 + 自定义控制程序
conda run -n simulation python app.py --no-gui --control-program my_tracker:MyTracker --delay-ms 20 --duration 10

# 航点 + 自定义控制程序 + research 模式
conda run -n simulation python app.py --no-gui --waypoints "(100,0,20,2),(80,30,10,1.5),(60,0,0,0)" \
    --control-program my_tracker:MyTracker --obs-mode research --duration 20
```

## 5. 典型研究流程

完整研究流程从运行 benchmark 到生成对比图，详见[研究工作流手册](研究工作流手册.md)。

快速概览：

```
run_benchmark.py → summarize_results.py → compare_results.py
       ↓                                          ↓
  result.json + metrics.csv              diagnose_algorithm.py
       ↓                                          ↓
  summary.json + summary.csv            plot_comparison.py
```

### 5.1 一键 benchmark

```bash
conda run -n simulation python tools/run_benchmark.py --algorithms atp_search_track_baseline rate_pi --scenarios B1 B2 --duration 20
```

### 5.2 汇总结果

```bash
conda run -n simulation python tools/summarize_results.py --input-dir output/experiments
```

### 5.3 对比两个版本

```bash
conda run -n simulation python tools/compare_results.py --baseline output/experiments --new output/experiments_v2
```

### 5.4 诊断退化算法

```bash
conda run -n simulation python tools/diagnose_algorithm.py --algorithm linear_kf_tracker --scenario B3
```

### 5.5 生成对比图

```bash
conda run -n simulation python tools/plot_comparison.py --input-dir output/experiments --plots all
```

## 6. 输出结果怎么看

### 6.1 实时仿真输出

无 GUI 模式下，控制台每 tick 输出：
```
t=1.000 yaw=12.34 u=23.45 v=-5.67 in_fov=True backlog=0 obs_lag=0.012
```

### 6.2 benchmark 输出结构

```
output/experiments/
  ├── summary.csv              # 逐条实验汇总
  ├── summary_grouped.csv      # 按算法×场景分组
  ├── summary.json             # 结构化汇总
  └── {scenario_id}/{condition_id}/{algorithm}/seed_{n}/
        ├── result.json        # 汇总指标（capture_rate, rms_error, atp_metrics 等）
        ├── metrics.csv        # 逐 tick 数据（pixel_error, atp_state, yaw/pitch_rate_cmd）
        ├── notes.md           # 实验元信息
        ├── error_curve.png    # 误差曲线图
        └── state_timeline.png # ATP 状态时间线图
```

### 6.3 关键指标解读

| 指标 | 含义 | 好的范围 |
|------|------|---------|
| `capture_success_rate` | 跟踪成功率 | ≥ 0.95 |
| `rms_pixel_error` | 均方根像素误差 | 越小越好 |
| `tracking_efficiency` | 跟踪效率 | ≥ 0.90 |
| `lock_loss_count` | 丢锁次数 | 0 |
| `time_to_fine_track_s` | 收敛到精跟踪时间 | 越小越好 |
| `state_distribution.TRACK_FINE` | 精跟踪占比 | 越高越好 |

### 6.4 ATP 状态分布

`result.json` 中的 `atp_metrics.state_distribution` 直接反映算法在哪个阶段：
- 理想情况：`{"TRACK_FINE": 1.0}` — 全程精跟踪
- 有丢失：包含 SEARCH/REACQUIRE — 说明算法在某些时段丢失目标
- 频繁丢锁：LOST/SEARCH 占比高 — 需要诊断

## 9. 常见问题

**Q: GUI 黑屏/无窗口？**
A: 需在本机图形环境运行。远程 SSH 请使用 `--no-gui`。

**Q: 显示"未 READY"？**
A: 系统会自动等待实体启动。超时请检查配置。

**Q: `--target-type` 在 GUI 模式下是否生效？**
A: 已修复。`--target-type` 和 `--waypoints` 在 GUI 模式和 headless 模式下均可正常使用。

**Q: 如何加载自己的控制程序？**
A: 将 `.py` 文件放在 `systemSimulation/` 下，使用 `--control-program 文件名:类名` 加载。详见[树莓派控制程序开发手册](树莓派控制程序开发手册.md)。

**Q: benchmark 输出在哪里？**
A: 默认在 `output/experiments/`。可通过 `--output-dir` 指定其他路径。

**Q: 如何查看 ATP 状态？**
A: benchmark 的 `metrics.csv` 中逐 tick 记录了 `atp_state` 字段；`result.json` 中有 `state_distribution` 汇总。

## 10. 目录结构

```
systemSimulation/
├── app.py                          # 主入口（透传到 simulation.cli）
├── config.py                       # 全局配置（dataclass）
├── runtime/
│   ├── digital_twin_runtime.py     # 世界时钟、命令总线、tick 调度
│   └── types.py                    # Command、WorldSnapshot 等核心类型
├── simulation/
│   ├── bootstrap.py                # build_runtime()、start_stack()
│   ├── cli.py                      # 参数解析 + 入口分发
│   ├── headless.py                 # 无 GUI 运行入口
│   └── gui/
│       └── window.py               # PyQt5 实时仪表盘
├── entities/
│   ├── target/                     # 目标实体（5 种运动模型）
│   ├── gimbal/                     # 云台实体（串级 PID、双轴）
│   ├── camera/                     # 相机实体（双轴针孔成像）
│   └── raspi/                      # 树莓派实体（延时管线、控制程序）
│       ├── atp_control_program.py  # ATP 可插拔控制器
│       ├── atp_state_machine.py    # ATP 状态机
│       ├── trackers/               # 跟踪器（RateP/RatePI/AngleMode）
│       └── predictors/             # 预测器（AlphaBeta/LinearKF）
├── tools/                          # 16 个工具脚本
├── tests/                          # 单元测试 + 集成测试
└── docs/                           # 文档体系
```

## 附录：参数速查表

### 运动类型参数

| 类型 | 关键参数 | 说明 |
|------|---------|------|
| `sinusoidal` | amplitude_m, frequency_hz | 正弦横移 |
| `constant_velocity` | velocity_mps, direction_rad | 匀速直线 |

| `random_walk` | sigma_m, mean_reversion_rate | 随机游走 |

### 观测模式

| 模式 | 可见信息 | 适用场景 |
|------|---------|---------|
| `debug` | 全量（含目标真值） | 开发调试 |
| `research` | 不含目标真值 | 算法研究 |
| `realistic` | 含传感器噪声 | 近真实验证 |

### 已注册算法

| 算法名 | 类型 | 说明 |
|--------|------|------|
| `baseline_rate_p` | 直接控制 | 基线 P 控制器（无 ATP 状态机） |
| `atp_search_track_baseline` | ATP + RateP | 搜索-捕获-跟踪 + P 控制器 |

| `alpha_beta_tracker` | ATP + RateP + AlphaBeta | ATP + P 控制器 + α-β 预测 |
| `linear_kf_tracker` | ATP + RateP + LinearKF | ATP + P 控制器 + 卡尔曼预测 |
| `angle_mode_realistic` | 角度模式 | 直接角度控制（需 realistic/debug） |
