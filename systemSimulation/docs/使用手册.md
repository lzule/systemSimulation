## 1. 架构总览

系统由 4 个实体 + 1 个 Runtime 调度器组成：

- **Target**：目标运动体，输出世界坐标
- **Gimbal**：两轴云台，执行角度/角速度控制
- **Camera**：挂载在云台上的相机，根据姿态成像
- **Raspi**：树莓派控制器，检测目标并输出控制命令

每个 tick 固定顺序：`收命令 → Target → Gimbal → Camera → Raspi → 发布快照`

详细的实体间数据流和组合使用方式参见 [主 README](../README.md)。

## 2. 快速开始

```bash
# 默认环境：conda 的 simulation 虚拟环境

# 无 GUI 快速验证
conda run -n simulation python app.py --no-gui --mode offline --duration 1.0

# GUI 实时仿真
conda run -n simulation python app.py --mode realtime --duration 60
```

成功判据：
- 出现 `[app/headless] mode=...` 启动行
- 周期输出 `t=... yaw=... u=... in_fov=...`
- 无异常堆栈

## 5. 代码规范与目录规范

### 5.1 命名规范
- 变量名带物理单位后缀：`_s/_hz/_deg/_dps/_mm/_px`
- 控制变量使用语义名：`pixel_error_x`、`yaw_rate_cmd_dps`

### 5.2 注释与类型
- 非直观逻辑必须写中文注释（时序、坐标系、限幅、状态机）
- 新增函数建议补齐类型注解

### 5.3 目录约束
- 新能力优先放 `entities/*` 与 `runtime/*`
- 应用层编排放 `simulation/*`
- 临时脚本放 `workspace_meta/tmp_scripts/`
- 运行产物放 `output/`
- 迭代记录放 `workspace_meta/plan_logs/`

### 5.4 文档维护
每次变更同步更新：
- 对应实体的 `README.md`
- `README.md`（如有组装关系变更）
- `workspace_meta/plan_logs/latest_plan.md` 和 `history.md`

## 6. 验收清单

### 6.1 基础编译检查
```bash

```

### 6.2 单实体回归
```bash
conda run -n simulation python -m unittest discover -s entities\gimbal\tests -p "test_*.py" -v

conda run -n simulation python -m unittest discover -s entities\raspi\tests -p "test_*.py" -v
```

### 6.3 主线回归
```bash
conda run -n simulation python -m unittest discover -s tests -v
```

### 6.4 组装冒烟
```bash
conda run -n simulation python app.py --no-gui --mode offline --duration 1.0
```

### 6.5 通过标准
- 所有测试通过
- 无 GUI 冒烟输出连续、无异常终止
- 关键字段（yaw/pitch/u/v/in_fov/backlog）正常刷新

## 附录：建议的日常工作节奏

1. 先改单实体并跑该实体测试
2. 再跑 `tests/` 做主线回归
3. 最后跑 headless 或 GUI 冒烟看系统级行为
4. 更新对应实体 README + 计划日志 + agent_log
5. 进入下一轮
