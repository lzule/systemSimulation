## 1. 本阶段要解决什么

当前系统是纯 2D 单轴原型：

- 目标只有 x, y，无 z 坐标
- 相机 v 坐标硬编码为 `h/2.0`（[camera/model.py:32](../../entities/camera/model.py#L32)），目标始终在图像垂直中心
- 跟踪器 pitch_rate 恒为 0（[raspi/tracker_program.py:130](../../entities/raspi/tracker_program.py#L130)）
- bearing 是 2D 方位角，无俯仰角

本阶段把系统从"一轴亮点跟踪原型"升级为"双轴 ATP 几何与控制底座"，使系统能处理含高度变化的目标。

---

## 2. 本阶段不做什么

1. 不实现 ATP 状态机（捕获/粗跟踪/精跟踪/失锁恢复）— 阶段 4。
2. 不实现 obs_filter — 阶段 3。
3. 不增加近真实建模（丢检、噪声增强、多目标）— 阶段 3。
4. 不增加通信链路仿真 — 下一轮。

## 4. 执行顺序与任务拆分

### 任务 1：统一坐标系定义文档（最先完成）

**目标**：所有后续角度计算都以这份文档为基准。

**具体动作**：

1. 定义世界坐标系：ENU（东-北-天），原点在云台位置，x=东，y=北，z=天。
2. 定义视线角：
   - azimuth = atan2(y, x)，从 x 轴正方向（东）逆时针计量（与当前 `bearing_deg = atan2(y, x)` 完全一致，z=0 时数值不变）
   - elevation = atan2(z, sqrt(x²+y²))，仰角为正
3. 定义云台姿态：yaw 正方向与 azimuth 一致，pitch 正方向为仰角方向（向上为正），零位为水平。
4. 定义像素投影：alpha = azimuth - yaw，beta = elevation - pitch，u = f×tan(alpha)+cx，v = cy - f×tan(beta)。这一定义与“beta > 0 表示目标在视线上方、画面应出现在中心上方”保持一致。
5. 图像坐标规则：u 向右增，v **向下**增。目标出现在画面上方时 `det.cy < cy`，此时 beta > 0（目标在视线上方），pitch 应向正方向（向上）跟踪；目标出现在画面下方时 `det.cy > cy`，此时 beta < 0，pitch 应向负方向跟踪。文档、公式、测试三处必须保持这套符号关系完全一致。
6. 坐标系文档必须包含 4 个数值示例：`+x` 方向 `(x=100,y=0,z=0)`、`+y` 方向 `(x=0,y=100,z=0)`、`-x` 方向 `(x=-100,y=0,z=0)`、`-y` 方向 `(x=0,y=-100,z=0)`，各输出 azimuth 和 elevation 的精确值。不要再使用“正前方/正后方”这类带主观朝向含义的命名。
7. 写入独立文档：`docs/阶段2-双轴ATP升级/坐标系定义.md`

**涉及文件**：新增文档
**改动范围**：仅文档
**前置依赖**：无

### 任务 2：升级目标模型为 3D

**目标**：TargetKinematics2D → TargetKinematics3D，支持 z 坐标。

**具体动作**：

   - `bearing_deg` 改名 `azimuth_deg`（保持向后兼容，新增属性别名）
   - 新增 `elevation_deg = atan2(z, sqrt(x²+y²))`
   - `distance_m` 改为 `sqrt(x²+y²+z²)`
2. `entities/target/entity.py`：
   - `TargetState` 增加 `z_m, vz_mps, elevation_deg`
   - `get_state()` 输出增加对应字段

4. `simulation/headless.py`：
   - 航点解析支持 `(x, y, z, speed)` 格式，z 缺省为 0

**涉及文件**：entities/target/model.py, entities/target/entity.py, config.py, simulation/headless.py

**兼容性策略**：

### 任务 3：重构相机投影模型为双轴

**目标**：v 坐标根据 elevation - pitch 计算，不再是硬编码。

**具体动作**：

1. `entities/camera/model.py`：
   - `render_beacon_frame()` 签名扩展：接收 `alpha_rad`（水平偏差）和 `beta_rad`（垂直偏差）
   - `v = cy - f_px * tan(beta_rad)`（替换 `v = h/2.0`，确保 beta > 0 时目标出现在画面上方）
   - `in_fov` 改为双轴判断：`abs(alpha_rad) <= fov_h_half and abs(beta_rad) <= fov_v_half`
   - 新增垂直 FOV 计算（基于 sensor_h_mm 和 focal_length_mm）
   - 高斯 blob 的 v 中心从 `cy` 改为 `v` 计算值
2. `entities/camera/entity.py`：
   - `update()` 中计算 `beta = elevation - pitch`（与当前 alpha 计算对称）
   - 传递 `alpha_rad, beta_rad` 给 `render_beacon_frame()`
   - 输出 `v_px` 使用真实投影值

3. `config.py` CameraConfig 部分：
   - 新增 `fov_v_deg` 属性（= 2 × atan(sensor_h_mm / (2 × focal_length_mm))），与水平 FOV 对称
   - 在 `CameraConfig` 类中明确注释垂直 FOV 的计算来源

**涉及文件**：entities/camera/model.py, entities/camera/entity.py, config.py
**改动范围**：大
**前置依赖**：任务 2（需要 target 输出 elevation_deg）

## 6. 风险点与控制方式

### 风险 1：坐标系定义与当前隐式约定冲突

当前代码中 `bearing_deg = atan2(y, x)`（见 `entities/target/model.py:98-99`、`entities/camera/entity.py:119`）。azimuth 定义必须与此完全一致：`azimuth = atan2(y, x)`。

**控制**：坐标系文档中唯一写死 `azimuth = atan2(y, x)`，不再出现第二种写法。实现后测试中首先验证"z=0 时 azimuth 与当前 bearing 数值完全一致"。

### 风险 2：2D→3D 升级破坏全部测试

**控制**：z 相关参数全部默认为 0。第一轮验证先跑全部旧测试，确认 z=0 下行为不变。只修复因字段名变更（如 bearing→azimuth 别名）导致的断裂。

### 风险 3：FOV 垂直方向定义不清

当前只有水平 FOV（`fov_h_deg`）。双轴需要垂直 FOV。

**控制**：在 CameraConfig 中新增 `fov_v_deg` 属性（基于 sensor_h_mm 计算），与水平 FOV 对称。FOV 判断改为双轴 AND 条件。

### 风险 4：pitch 限位导致 v 坐标异常

pitch 有物理限位 [-135°, +90°]。当目标在限位外时，v 坐标可能超出图像范围。

**控制**：这是正常行为——in_fov 判断会自动排除超出 FOV 的目标。测试中增加限位附近的边界用例。
