## 1. 本阶段要解决什么

当前项目已经完成阶段 0 的基线收口，但“低空场景无线光通信 ATP”还没有被严格定义成一个可研究、可评测、可对比、可复现实验的问题。

如果跳过这个阶段直接往后做，会出现四类问题：

1. 同一个算法在不同实验里实际面对的是不同任务，结果不可比。
2. 指标会边做边改，后面无法形成稳定结论。
3. 场景和参数命名会各写一套，最后无法统一统计。
4. 当前 2D/1 轴平台和后续 3D/双轴平台之间会出现定义冲突。

所以阶段 1 的目标是：**一次性冻结问题定义、场景矩阵、工况维度、指标体系、观测模式边界和实验输出规范。**

---

## 2. 本阶段不做什么

本阶段只做定义和规范，不做下列实现性工作：

1. 不做 2D→3D 升级。
2. 不做双轴投影和双轴控制改造。
3. 不做 `obs_filter` 代码实现。
4. 不做通信链路仿真。
5. 不做算法接入与 benchmark 跑数。
6. 不做硬件选型和样机结构设计。

## 4. 执行顺序与任务拆分

### 任务 1：冻结研究问题定义

目标：
把平台研究对象、任务链、边界和成功判据写成单一口径。

具体动作：

1. 明确平台定位是“低空场景无线光通信 ATP 研究与方法筛选平台”，不是高保真数字孪生样机。
2. 明确研究主链为：
   - 捕获
   - 粗跟踪
   - 精跟踪
   - 稳定瞄准
   - 通信保持（本轮仅接口预留）
   - 失锁恢复
3. 明确通信相关内容在本轮只保留接口和评价位置，不进入本轮实际联合仿真。
4. 明确当前阶段成功定义以 ATP 为主，不以通信链路可用率作为本轮闸门。

阶段成果：
- `阶段1问题定义文档.md`

前置依赖：
- 无

工作量：
- 中

### 任务 2：冻结目标场景矩阵

目标：
固定后续可使用的标准场景编号、用途和当前表达边界。

具体动作：

1. 冻结一级场景：
   - `S1` 地面站-低空飞行器
   - `S2` 地面站-地面小车
   - `S3` 地面站-一般移动目标
   - `S4` 双移动体扩展场景
2. 为每个场景标注：
   - 当前是否可由 2D 平台直接表达
   - 当前是否只能写成 2D 简化版
   - 需在哪个后续阶段补齐 3D 完整定义
3. 对低空飞行器场景明确写清：
   - 阶段 1 仅冻结 2D 简化版
   - 阶段 2 完成 3D 升级后补齐高度和俯仰工况
4. 对当前尚不存在的遮挡、多目标、干扰目标仅做定义冻结，不伪装成已支持。

阶段成果：
- `阶段1场景矩阵与工况定义.md`

前置依赖：
- 任务 1

工作量：
- 高

### 任务 3：冻结工况维度与分档

目标：
为每个标准场景定义统一难度维度，并标注其与当前平台能力的关系。

具体动作：

1. 固定工况维度：
   - 距离
   - 速度
   - 角速度
   - 机动强度
   - 遮挡
   - 延时
   - 扰动
2. 每个维度必须写清：
   - 含义
   - 单位
   - 建议分档
   - 当前是否可表达
   - 当前对应配置项
   - 若当前不可表达，需后续新增什么配置项或能力
3. 已有直接配置入口的维度要给出确切字段名。
4. 只能间接表达的维度要说明是由哪些字段组合决定。
5. 当前完全不支持的维度要标明建议实现阶段。

阶段成果：
- 并入 `阶段1场景矩阵与工况定义.md`

前置依赖：
- 任务 2

工作量：
- 高

### 任务 4：冻结 ATP 指标体系

目标：
固定后续平台评价 ATP 能力时的核心指标、计算边界和当前可计算状态。

具体动作：

1. 冻结核心 ATP 指标：
   - 捕获成功率
   - 捕获时间
   - 稳态误差
   - 峰值误差
   - 失锁率
   - 重捕获时间
2. 对每个指标写清：
   - 定义
   - 计算窗口
   - 单位
   - 优化方向
   - 当前是否可自动计算
   - 若不可自动计算，缺失什么能力
   - 是否属于阶段闸门指标
3. 把阶段 0 已知基线值挂到指标体系中，作为分档参考零点。
4. 区分“当前即可测的子集”和“后续阶段待实现的子集”。

阶段成果：
- `阶段1指标体系与判定规则.md`

前置依赖：
- 任务 1
- 任务 3

工作量：
- 高

### 任务 5：冻结通信指标接口定义

目标：
为下一轮 ATP+通信联合仿真预留统一评价接口，但不把通信指标纳入本轮实测闸门。

具体动作：

1. 冻结通信侧指标名称：
   - 接收功率
   - 链路余量
   - 通信可用率
   - 中断次数
   - 最长连续中断时长
2. 明确这些指标在阶段 1 只做接口定义和字段占位。
3. 明确这些指标不属于本轮 6 个阶段的实际验收对象。
4. 明确它们将在下一轮 ATP+通信联合仿真中进入正式实验。

阶段成果：
- 并入 `阶段1指标体系与判定规则.md`

- 任务 4

### 任务 6：冻结三种观测模式边界

目标：
先定义平台对算法开放哪些输入，不提前做代码过滤实现。

具体动作：

1. 定义调试模式。
2. 定义研究模式。
3. 定义近真实模式。
4. 为每种模式写清：
   - 输入白名单
   - 输入黑名单
   - 允许读取的信息类别
   - 禁止直接读取的真值类别
   - 适用阶段
5. 明确阶段 1 只冻结输入边界，阶段 3 才实现 `obs_filter`。

1. 先产出 `阶段1问题定义文档.md`
2. 再产出 `阶段1场景矩阵与工况定义.md`

4. 再产出 `阶段1观测模式与输入边界.md`
5. 再产出 `阶段1实验输出规范.md`
6. 最后产出 `阶段1评审清单.md`

原因：

1. 问题定义不稳定，场景矩阵就不稳定。
2. 场景和工况不稳定，指标体系就无法冻结。
3. 指标和观测边界不稳定，输出规范会反复返工。

## 7. 风险点与控制方式

### 风险 1：问题定义过大

控制方式：
- 本阶段只冻结研究问题和实验口径。
- 硬件、小型化和样机实施另行管理。

### 风险 2：指标定义脱离当前平台

控制方式：
- 每个指标都标注当前是否可自动计算。
- 不可自动计算的指标必须写清依赖的后续能力。

### 风险 3：场景定义与阶段 2 冲突

控制方式：
- 所有涉及低空飞行器和高度变化的场景必须标注“当前仅 2D 简化定义，阶段 2 补齐 3D 完整定义”。

### 风险 4：工况维度没有配置入口

控制方式：
- 每个工况维度都必须标注当前配置字段或未来新增项。

### 风险 5：通信指标越界进入本轮验收

控制方式：
- 明确通信指标只做接口预留，不纳入本轮 6 个阶段的正式验收。

### 风险 6：冻结后被随意修改

控制方式：
- 建立冻结后修订流程，要求重新复核受影响项。
