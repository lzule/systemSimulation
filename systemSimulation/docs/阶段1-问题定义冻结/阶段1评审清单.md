# 阶段1评审清单

> 阶段：阶段 1「问题定义冻结」

## 1. 使用方式

本清单有两个用途：

1. 阶段 1 结束时做一次收口审查
2. 后续阶段若要修改阶段 1 定义，作为修订复核入口

## 2. 阶段 1 收口检查项

### 2.1 问题定义

- [x] 平台定位是否唯一且无冲突
- [x] 本轮是否明确以 ATP 平台本体为主，而非 ATP+通信联合仿真
- [x] 是否明确当前平台不是高保真数字孪生样机
- [x] 任务链是否完整包含捕获、粗跟踪、精跟踪、稳定瞄准、通信保持（接口预留）、失锁恢复

### 2.2 场景矩阵

- [x] 场景编号是否固定为 `S1`~`S4`
- [x] 每个场景是否都标明当前 2D 可表达性
- [x] 低空飞行器场景是否明确写为”当前仅 2D 简化版，阶段 2 补齐 3D”
- [x] 双移动体/遮挡/干扰目标是否只冻结定义，没有误写成已支持

### 2.3 工况维度

- [x] 距离、速度、角速度、机动强度、遮挡、延时、扰动是否全部定义
- [x] 每个维度是否都标明”当前可表达性”
- [x] 每个维度是否都标明”当前配置字段”或”后续新增项”
- [x] 是否给出了推荐标准组合，避免实验空间失控

### 2.4 ATP 指标

- [x] 捕获成功率、捕获时间、稳态误差、峰值误差、失锁率、重捕获时间是否全部冻结
- [x] 每个指标是否都写清定义、窗口、单位、方向
- [x] 每个指标是否都标明”当前可自动计算 / 待后续实现”
- [x] 是否已经挂接阶段 0 的基线锚点
- [x] 支持性指标（跟踪率、收敛时间、不发散判定）是否已标注为非核心但当前可用的补充指标

### 2.5 通信指标

- [x] 接收功率、链路余量、通信可用率、中断次数、最长连续中断时长是否全部冻结命名
- [x] 是否明确这些指标只是接口预留
- [x] 是否明确这些指标不纳入本轮 6 个阶段正式验收

### 2.6 观测模式

- [x] 调试模式、研究模式、近真实模式是否都已定义
- [x] 每种模式是否都给出输入白名单
- [x] 每种模式是否都给出输入黑名单
- [x] 是否明确阶段 1 只定义边界、阶段 3 才实现 `obs_filter`

### 2.7 实验输出规范

- [x] 是否已固定最小输出字段
- [x] `key_params` 是否明确直接复用阶段 0 dataclass 字段名
- [x] 是否禁止另起参数别名体系
- [x] 是否固定目录结构、JSON/CSV 字段和最小图表集合

### 2.8 主开发文档一致性

## 4. 冻结后修订流程

若后续阶段需要修改阶段 1 定义，必须按以下流程执行：

1. 明确修订原因
2. 明确受影响文档
3. 明确受影响场景、指标或输出字段
4. 在本清单中重新复核相关条目
5. 在主开发文档和变更记录中同步留下修订记录

禁止：

1. 不留说明直接改定义
2. 只改单一文档，不同步其他口径
3. 把“当前未实现”的内容改写成“已支持”
