# 阶段1实验输出规范

> 阶段：阶段 1「问题定义冻结」
> 状态：正式冻结文档（2026-05-15 评审通过）
> 作用：统一后续实验结果字段、参数命名、目录结构和最小图表集合

---

## 1. 基本原则

1. 同类实验必须输出同一组核心字段。
2. 参数命名必须直接复用阶段 0 已冻结的 dataclass 字段名。
3. 结果目录和文件命名必须可批量比较、可批量统计。
4. 通信指标当前只保留占位字段，不要求本轮填入真实值。

---

## 2. 最小结果字段

每次实验至少输出以下字段：

| 字段名 | 含义 |
|---|---|
| `experiment_id` | 实验唯一编号 |
| `timestamp` | 结果生成时间 |
| `scenario_id` | 场景编号，如 `S2` |
| `condition_id` | 工况编号，如 `B1` |
| `observation_mode` | 观测模式 |
| `algorithm_name` | 算法名称 |
| `algorithm_version` | 算法版本或分支标识 |
| `seed` | 随机种子 |
| `config_profile` | 使用的配置来源说明 |
| `key_params` | 关键参数集合 |
| `metrics_atp` | ATP 指标结果 |
| `metrics_comm_placeholder` | 通信指标占位字段 |
| `artifacts` | 图表、日志、回放文件位置 |
| `notes` | 备注 |
| `failure_reason` | 失败原因，若实验失败必须填写 |

---

## 3. 参数命名规范

### 3.1 唯一命名来源

`key_params` 字段必须直接复用阶段 0 研究基线配置中的字段名。

允许直接引用的字段来源包括：

1. `TargetConfig`
2. `GimbalConfig`
3. `AxisLimitConfig`
4. `LoopConfig`
5. `ControlPreset`
6. `CameraConfig`
7. `RaspiConfig`
8. `RaspiDelayConfig`
9. `TrackerTuningConfig`
10. `YawDisplayConfig`
11. `SceneConfig`

### 3.2 禁止事项

禁止：

1. 把 `yaw_rate_kp_dps_per_px` 改写成 `kp`
2. 把 `image_process_delay_s` 改写成 `process_delay`
3. 另起一套与阶段 0 不兼容的别名

### 3.3 推荐写法

`key_params` 中优先保留：

1. 与当前实验直接相关的字段
2. 与算法差异直接相关的字段
3. 与工况差异直接相关的字段

---

## 4. 结果目录结构

统一采用以下目录结构：

```text
output/
  experiments/
    <scenario_id>/
      <condition_id>/
        <algorithm_name>/
          <experiment_id>/
            result.json
            metrics.csv
            error_curve.png
            state_timeline.png
            notes.md
```

说明：

1. 场景在最外层，便于横向比较。
2. 工况次级分组，便于同场景下做难度递进。
3. 算法再分组，便于同条件多方法对比。

## 6. CSV 结果字段

若输出表格化汇总，最少包含以下列（字段名与指标体系文档对齐）：

| 列序 | 字段名 | 对应指标编号 | 说明 |
|---|---|---|---|
| 1 | `experiment_id` | — | 实验编号 |
| 2 | `scenario_id` | — | 场景编号 |
| 3 | `condition_id` | — | 工况编号 |
| 4 | `observation_mode` | — | 观测模式 |
| 5 | `algorithm_name` | — | 算法名称 |
| 6 | `seed` | — | 随机种子 |
| 7 | `angle_error_rms_deg` | A3 | 稳态角度误差 RMS |
| 8 | `angle_error_max_deg` | A4 | 稳态角度峰值误差 |
| 9 | `pixel_error_rms_px` | A3 | 稳态像素误差 RMS |
| 10 | `tracking_ratio` | — | 稳态跟踪率 |
| 11 | `capture_success_rate` | A1 | 捕获成功率 |
| 12 | `capture_time_s` | A2 | 捕获时间 |
| 13 | `lock_loss_rate` | A5 | 失锁率 |
| 14 | `reacquire_time_s` | A6 | 重捕获时间 |
| 15 | `failure_reason` | — | 失败原因 |

说明：

1. 当前尚不能自动计算的字段（A1/A2/A5/A6 对应列）允许留空。
2. 但字段名必须提前固定，避免后面改 schema。
3. 后续新增通信指标列时，统一加在本表末尾。

---

## 7. 最小图表集合

后续标准实验默认至少输出：

1. 误差曲线图
2. 跟踪状态时间线
3. 关键指标汇总表

若后续进入下一轮 ATP+通信联合仿真，再增加：

1. 接收功率曲线
2. 链路可用率时间线
3. 中断统计图

---

## 8. 失败结果规范

实验失败时，不允许只写“失败”。

必须至少记录：

1. 失败时间
2. 失败原因分类
3. 是否进入失锁
4. 是否出现发散
5. 是否因输入模式限制导致

---

## 9. 与阶段 0 的衔接

1. `config_profile` 默认引用阶段 0 冻结基线。
2. `key_params` 默认从阶段 0 冻结字段中选取。
3. 后续阶段新增参数时，必须在现有字段体系上增量扩展。
