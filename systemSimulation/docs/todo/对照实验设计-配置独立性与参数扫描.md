## 1. Context

### 1.1 问题背景

用户希望进行对照试验，**验证、测量系统中哪些实例指标对整个系统的跟踪性能有影响，影响有多大**。具体子目标：

- **TODO 2.a**：相机硬件帧率与延时（30/60/120fps）对跟踪性能影响
- **TODO 2.b**：树莓派图像处理延时（10/16.7/25/33/40/50ms）对跟踪性能影响
- **TODO 2.d**：为公平对比，每个条件需分别将 P 控制 Kp 调到最优；展示 Kp 与改变的系统参数的关系

### 1.2 现状评估

- 已有 `tools/frame_rate_experiment.py`（30/60fps + Kp 扫参雏形，含 Phase A/B/C）
- 已有 `tools/tune_tracker_kp.py`（单 Kp 扫参）
- 已有 `tools/run_benchmark.py`（多算法、多场景、多 seed benchmark 框架）
- **缺少**：统一的对照实验框架、独立的实验目录、跨实验的 Kp 趋势分析

### 1.3 关键决策（用户已确认）

| 决策项 | 选择 | 理由 |
|--------|------|------|
| 延时实验的"延时"定义 | 仅图像处理延时 `image_process_delay_s`，其他阶段保持默认 | 更精确的"图像处理"语义；通过 `set_delay_profile()` 注入 |
| Kp 调优范围 | 仅树莓派视觉跟踪 Kp（`TrackerTuning`） | 闭环最外层 P 控制，与帧率/延时最直接相关；云台级联 PID 保持默认 |
| yaw/pitch 是否同步 | 分别独立扫参（二维网格） | 更严谨；可验证 pitch_kp 对正弦轨迹的不敏感性 |
| 是否纳入 TODO 2.c | 不纳入 | TODO 当前跳过 c，仅做 a/b/d |
| 实验代码与数据管理 | **建立独立 `experiments/` 一级目录** | 后续会做大量实验，避免散落在 `tools/` 和 `output/` |

## 2. 实验目录规划（核心）

新建 `systemSimulation/experiments/` 一级目录，统一管理所有对照实验：

```
systemSimulation/experiments/
├── README.md                          # 实验目录索引、命名规范、共用约定
├── common/                            # 共用框架代码
│   ├── __init__.py
│   ├── experiment_runner.py           # 统一实验框架（条件→Kp扫参→多seed→报告）
│   ├── kp_grid_search.py              # 二维 Kp 网格搜索
│   ├── metrics_collector.py           # 指标计算（复用 tools/run_benchmark.py 的逻辑）
│   └── plot_utils.py                  # 可视化通用工具
├── exp01_camera_fps/                  # 实验1：相机帧率
│   ├── README.md                      # 实验目的、参数空间、结论
│   ├── run.py                         # 实验入口脚本
│   ├── config.yaml                    # 实验参数（fps列表、Kp范围、seed等）
│   └── data/                          # 实验产出（CSV / PNG / JSON）
│       ├── kp_grid/                   # 各条件下 Kp 二维搜索结果
│       ├── multi_seed/                # 最优 Kp 下多 seed 验证
│       ├── optimal_kp_table.csv       # 各条件最优 Kp 汇总
│       └── report/                    # 最终报告（PNG + MD）
├── exp02_raspi_process_delay/         # 实验2：树莓派图像处理延时
│   ├── README.md
│   ├── run.py
│   ├── config.yaml
│   └── data/
│       ├── kp_grid/
│       ├── multi_seed/
│       ├── optimal_kp_table.csv
│       └── report/
└── docs/                              # 实验相关的设计/审查文档
    ├── 配置独立性审查报告.md           # Phase A 产出
    └── 实验目录使用规范.md             # 后续新实验如何复用框架的指南
```

**命名规范**：`expNN_<实验主题>` 数字编号 + 主题描述（雪花式扩展，后续新实验自然递增）

**复用规范**：
- `common/` 是所有实验共用代码，**禁止**在 `expNN_*/` 内复制粘贴
- 每个实验只写自己独有的逻辑（参数空间、特殊处理）
- 数据严格放在 `expNN_*/data/`，**禁止**写入 `output/`

## 3. Phase A：配置独立性审查（只读）

### 3.1 逐实体核对

| 实体 | 配置引用 | 隔离性 | 备注 |
|------|---------|--------|------|
| **Camera** | `camera_cfg` 全局引用 | ❌ 无 deepcopy | `pixel_noise_std` 来自 `SceneConfig`；曝光/传输延时未独立建模 |
| **Gimbal** | 四个 cfg 全局引用 | ❌ 无 deepcopy | `max_velocity_dps` 与 `AxisLimitConfig.max_rate_dps` 语义重叠；yaw 无机械限位 |
| **Raspi** | `delay_cfg` 已 deepcopy | ✅ 隔离 | RaspiConfig 未 deepcopy，但实验改的是 delay_cfg |
| **Target** | `target_cfg` 已 deepcopy | ✅ 隔离 | — |

### 3.2 产出

`experiments/docs/配置独立性审查报告.md`：对照表 + 隔离等级（✅⚠️❌）+ 实验前是否需要解耦的结论

> **结论预判**：当前耦合不影响串行控制变量实验（实验脚本可显式构造实体绕过全局引用），并行批量跑时需先解耦。

## 10. 验证方案

### 10.1 中间验证

1. Phase B 完成后：用 `condition=fps=60, kp=1.1×1.1` 单点跑通，结果接近现有 baseline
2. Phase C/D Kp 扫参后：检查 RMS 曲面连续性、最优值附近平坦度
3. pitch_kp 扫参对正弦轨迹（XY 平面运动）应不敏感（pitch 误差小）→ 验证实验设计合理性

### 10.2 端到端验证

```bash

conda run -n simulation python -c "from experiments.common.experiment_runner import *; print('OK')"

# 2. 帧率实验冒烟（短跑 2s, 仅 fps=60, Kp 3×3 网格）
conda run -n simulation python experiments/exp01_camera_fps/run.py --smoke

# 3. 延时实验冒烟
conda run -n simulation python experiments/exp02_raspi_process_delay/run.py --smoke

# 4. 全量测试保持通过
```
