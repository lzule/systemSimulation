## 1. 总体对照表

| 实体 | 配置来源 | 构造方式 | 隔离 | 审查等级 |
|------|---------|---------|------|---------|

| **CameraEntity** | `camera_cfg` + `scene_cfg` | `copy.deepcopy(cfg or camera_cfg)` + `scene_cfg_obj` 构造参数 | ✅ `deepcopy` 隔离 + scene_cfg 可注入 | ✅ 安全（已修复） |

| **CameraImagingModel** | `camera_cfg` + `scene_cfg` | `copy.deepcopy(cfg or camera_cfg)` + `scene_cfg_obj` 构造参数注入 | ✅ `deepcopy` 隔离 + scene_cfg 可注入 | ✅ 安全（已修复） |

### 隔离等级颜色

- ✅ **隔离**：深拷贝或构造参数优先（不会被外部修改影响）
- ⚠️ **浅引用**：持有全局变量引用，可能被外部修改污染
- ❌ **外部引用**：不通过 self.cfg 访问，直接 import 模块级变量（**需要解耦**）

## 3. runtime 构造链总览

**DigitalTwinRuntime.__init__** (`runtime/digital_twin_runtime.py:29-53`):

```python
self.target = TargetEntity()       # → fallback target_cfg (deepcopy ✅)
self.gimbal = GimbalEntity()       # → fallback 4 个全局 cfg (全部 deepcopy ✅)
self.camera = CameraEntity()       # → fallback camera_cfg (deepcopy ✅) + scene_cfg 可注入 ✅
self.raspi = RaspiEntity()         # → fallback raspi_cfg + delay_cfg (全部 deepcopy ✅)
```

- 默认构造全部 fallback 到全局单例，但每个实体均 deepcopy 拥有独立副本
- `build_runtime()` (`simulation/bootstrap.py`) 不接受任何手动构造的 cfg 参数，是最高层封装
- 实验脚本可通过**直接构造各 Entity 并传入自定义配置**来控制实验变量

## 4. 结论与建议

### 4.1 审查结论（修复后）

> ✅ **全部实体配置完全隔离。** 所有 4 个实体 + CameraImagingModel + BaselineTrackerProgram 均已实现 deepcopy 或构造参数注入，不存在全局引用污染风险。单进程串行实验和多进程并行实验均安全。

### 4.2 已修复的解耦项

| 问题 | 位置 | 修复方案 |
|------|------|---------|
| `scene_cfg.pixel_noise_std` 外部引用 | `entities/camera/model.py` | `scene_cfg_obj` 构造参数注入 + `self._pixel_noise_std` ✅ |
| `tracker_tuning_cfg` 构造 fallback | `entities/raspi/tracker_program.py` | 直接使用 `TrackerTuning()` 默认值 ✅ |
| Entity 构造缺少 deepcopy（Gimbal/Camera/Raspi.cfg） | 各 entity.py `__init__` | 全部改为 `copy.deepcopy` ✅ |
| `detect_beacon_centroid` 隐式引用 `camera_cfg` | `entities/camera/entity.py` | `threshold` 默认值硬编码为 100 ✅ |

### 4.3 Phase B 框架设计建议

1. 多进程并行时**每个子进程独立 import**，天然避免所有配置污染问题 → 优先使用多进程
2. 单进程串行也可安全运行（所有配置已 deepcopy）
3. 实验变量（frame_rate_hz / image_process_delay_s / pixel_noise_std）应通过**构造新 dataclass 实例**传入
