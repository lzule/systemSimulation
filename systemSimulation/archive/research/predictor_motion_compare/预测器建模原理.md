# 预测器建模原理

本文档说明 `predictor_motion_compare` 研究中三种预测方法的数学建模、公式推导、适用场景与已知问题。

---

## 背景：为什么需要预测？

系统存在端到端延时。从观测捕获到云台命令生效，完整链路如下：

```
t = 0 ms      观测捕获（拍到目标像素位置 det.cx）
t = 6.5 ms    READING → PROCESSING（obs 读取完成）
t = 19.5 ms   PROCESSING → SENDING（控制程序执行，predict() 在此调用）
t = 26 ms     命令提交到 runtime
t = 31 ms     命令在云台生效（下一个 tick，dt = 5 ms）
```

以 `delay_ms = 26 ms`、`dt = 5 ms` 为例，**总延时约 31 ms**。

在这 31 ms 内目标继续运动。若不做预测，命令生效时目标已偏离 `det.cx`，产生系统性滞后误差。

**预测器的目标**：在 `t = 19.5 ms` 时，根据历史观测估计 `t = 31 ms` 时目标的像素位置，作为控制误差的参考点，实现前馈补偿。

---

## 坐标系与符号约定

| 符号 | 含义 |
|------|------|
| `u, v` | 目标在图像中的像素坐标（水平、垂直） |
| `cx, cy` | 图像中心像素坐标（光轴投影点） |
| `f_px` | 焦距（像素单位） |
| `dt` | 相邻两帧时间间隔（约 5 ms） |
| `T` | 预测时间跨度（= 总延时，约 31 ms） |
| `n_steps` | 预测步数，`T = n_steps × dt` |
| `α, β` | Alpha-Beta 滤波器平滑系数 |
| `Q, R` | 卡尔曼过程噪声、观测噪声协方差矩阵 |
| `ω` | 正弦分解候选角频率（rad/s） |

---

## 方法 0：无预测（基线）

### 建模

不做任何预测，直接用当前帧检测到的像素质心作为参考点。

```
ref_u = det.cx
error = ref_u - cx
rate_cmd = Kp × error
```

### 问题

命令生效时目标已运动了约 31 ms，误差为：

```
Δu ≈ vu × T
```

其中 `vu` 是目标像素速度（px/s），`T` 是总延时。对于快速运动目标，`Δu` 可达数十像素，导致持续滞后。

---

## 方法 1：Alpha-Beta 滤波器

### 建模

**状态向量**：`s = [u, v, vu, vv]ᵀ`（像素位置 + 像素速度）

**预测步**（每帧，无论是否有检测）：

```
u_pred = u + vu × dt
v_pred = v + vv × dt
```

**更新步**（有有效检测时）：

```
r_u = meas_u - u_pred        （位置残差）
r_v = meas_v - v_pred

u  ← u_pred  + α × r_u       （位置修正）
v  ← v_pred  + α × r_v
vu ← vu      + (β / dt) × r_u （速度修正）
vv ← vv      + (β / dt) × r_v
```

**外推**（predict，向前 n_steps 步）：

```
pred_u = u + vu × dt × n_steps
pred_v = v + vv × dt × n_steps
```

### 参数含义

| 参数 | 默认值 | 含义 |
|------|--------|------|
| `α` | 0.8 | 位置平滑因子，越大越信任当前测量 |
| `β` | 0.3 | 速度平滑因子，越大速度响应越快但噪声越大 |

### 适用场景与局限

- **匀速运动**：稳态误差为零，为最优线性估计
- **匀加速运动**：速度估计滞后，存在稳态误差 `≈ a × dt × β⁻¹`
- **正弦运动**：速度估计在峰谷处相位滞后，外推误差随频率增大

---

## 方法 2：线性卡尔曼滤波（LinearKF）

### 建模

**状态向量**：`x = [pu, pv, vu, vv]ᵀ`

**状态转移矩阵**（恒速模型）：

```
F = [[1, 0, dt,  0 ],
     [0, 1,  0, dt ],
     [0, 0,  1,  0 ],
     [0, 0,  0,  1 ]]
```

**观测矩阵**（只观测位置）：

```
H = [[1, 0, 0, 0],
     [0, 1, 0, 0]]
```

**过程噪声协方差**（对角简化）：

```
Q = diag([σ_pos² × dt,  σ_pos² × dt,  σ_vel² × dt,  σ_vel² × dt])
```

**观测噪声协方差**：

```
R = diag([σ_meas²,  σ_meas²])
```

### 滤波方程

**预测步**：

```
x̂⁻ = F × x̂
P⁻ = F × P × Fᵀ + Q
```

**更新步**（有有效检测时）：

```
y  = z - H × x̂⁻              （新息）
S  = H × P⁻ × Hᵀ + R          （新息协方差）
K  = P⁻ × Hᵀ × S⁻¹            （卡尔曼增益）
x̂  = x̂⁻ + K × y              （状态更新）
P  = (I - K × H) × P⁻         （协方差更新）
```

**外推**（predict，线性外推）：

```
pred_u = pu + vu × dt × n_steps
pred_v = pv + vv × dt × n_steps
```

### 与 Alpha-Beta 的关系

Alpha-Beta 是 KF 在恒速模型、稳态增益下的特例：

```
α = K[0,0]（稳态位置增益）
β = K[2,0] × dt（稳态速度增益 × dt）
```

两者外推公式完全相同，区别仅在于滤波质量：KF 通过协方差矩阵自适应调整增益，Alpha-Beta 使用固定增益。

### 适用场景与局限

- **匀速运动**：最优无偏估计（BLUE）
- **匀加速运动**：速度估计有稳态误差（模型不匹配）
- **正弦运动**：速度估计在峰谷处相位滞后，外推误差随振幅和频率增大

## 方法 3：正弦分解预测器（SineDecompositionPredictor）

### 设计思路

对于周期性运动（如正弦运动），目标像素轨迹可以分解为趋势项和振荡项。通过对历史观测做最小二乘拟合，估计振荡频率和幅度，然后外推到命令生效时刻。

### 建模

**拟合模型**（当前实现，存在问题）：

对候选角频率 `ω`，设计矩阵为：

```
Φ(t) = [1,  t,  t²,  sin(ωt),  cos(ωt)]
```

其中 `t` 为相对时间（以最后一个样本为原点，`t ≤ 0`）。

对历史窗口内的 N 个样本，求解最小二乘：

```
min_{c} ||Φ × c - u||²
c = (ΦᵀΦ)⁻¹ Φᵀ u    （由 numpy.linalg.lstsq 求解）
```

对 u 和 v 分别求解系数 `c_u, c_v`。

**频率选择**：在候选频率集合 `{ω₁, ω₂, ..., ωₙ}` 上遍历，选 RSS 最小的：

```
RSS(ω) = ||Φ(ω) × c_u - u||² + ||Φ(ω) × c_v - v||²
ω* = argmin RSS(ω)
```

候选频率范围：`[0.05, 1.0] Hz`，步数 30（线性均匀采样）。

**外推**（predict）：

```
horizon_s = last_dt × n_steps
φ(horizon_s) = [1,  horizon_s,  horizon_s²,  sin(ω* × horizon_s),  cos(ω* × horizon_s)]
pred_u = φ · c_u
pred_v = φ · c_v
```

### 当前实现的问题

#### 问题 1：t² 项导致模型过拟合

对正弦运动 `u(t) = A sin(2πft + φ₀)`，在短时间窗口内，`t²` 可以近似拟合正弦的局部曲率：

```
sin(ωt) ≈ ωt - (ωt)³/6 ≈ ωt    （小角度近似）
```

`t²` 项会与正弦项竞争，吸收部分能量，导致：
- 频率估计偏离真实值
- 外推时 `t²` 项以二次速度发散，正弦项被压制

**修复方向**：去掉 `t²`，设计矩阵改为 `[1, t, sin(ωt), cos(ωt)]`。

#### 问题 2：对非正弦运动强行拟合振荡项

匀速运动的真实模型是 `u(t) = u₀ + v × t`，无振荡分量。但正弦分解会从测量噪声中拟合出一个虚假频率，外推时虚假振荡放大，导致目标飞出视野（实验中 detected_rate 仅 30-60%）。

**修复方向**：增加纯线性候选 `[1, t]`，参与 RSS 竞争。匀速运动下线性模型 RSS 最小，自然退化为线性预测。

#### 问题 3：n_steps 硬编码为 3，外推量不足

```
horizon_s = last_dt × 3 = 5 ms × 3 = 15 ms
```

但命令生效延时约 31 ms，缺口 16 ms，预测补偿量只有实际需要的 48%。

**修复方向**：n_steps 由调用方根据实际延时动态计算：

```
n_steps = round(total_delay_s / dt_s)
        = round(31 ms / 5 ms)
        = 6
```

### 理想实现的适用场景

| 运动类型 | 理想正弦分解行为 |
|----------|----------------|
| 正弦运动 | 拟合真实频率，外推精度最高 |
| 匀速运动 | 退化为线性预测（线性候选赢得 RSS 竞争） |
| 匀加速运动 | 退化为线性预测（线性候选赢得 RSS 竞争） |
| 多频叠加 | 单频模型有残差，需扩展为多频模型 |

## 三种方法能力对比

| 方法 | 匀速 | 匀加速 | 正弦 | 计算量 | 延时补偿 |
|------|------|--------|------|--------|---------|
| 无预测 | 滞后 | 滞后 | 滞后 | 无 | 无 |
| Alpha-Beta | 最优 | 稳态误差 | 相位滞后 | 极小 | 线性外推 |
| LinearKF | 最优 | 稳态误差 | 相位滞后 | 小 | 线性外推 |
| 正弦分解（理想） | 退化线性 | 退化线性 | **最优** | 中等 | 频率外推 |
| 正弦分解（当前） | 发散 | 发散 | 不稳定 | 中等 | 不足 |

## 预测值接入控制链路的方式

预测器输出像素坐标 `(pred_u, pred_v)`，在 `RatePTracker.compute_commands` 中直接替换检测位置作为误差参考点：

```python
if prediction is not None:
    ref_u, ref_v = prediction          # 用预测位置替换当前检测位置
else:
    ref_u, ref_v = det.cx, det.cy      # 无预测时用当前检测位置

error_u = ref_u - cx_center            # 像素误差
rate_cmd = Kp × error_u                # P 控制
```

**语义**：`prediction` 应该是"命令生效时刻目标的像素位置"，而不是"当前时刻目标的像素位置"。因此 `n_steps` 必须对应从观测捕获到命令生效的总时间跨度，而不是任意步数。

## 已知问题汇总

| 编号 | 问题 | 影响 | 修复方向 |
|------|------|------|---------|
| P1 | 正弦分解设计矩阵含 `t²` 项 | 频率估计偏差，外推发散 | 去掉 `t²` |
| P2 | 正弦分解对非正弦运动无退化路径 | 匀速/匀加速场景目标丢失 | 增加线性候选参与 RSS 竞争 |
| P3 | `n_steps=3` 硬编码，外推量不足 | 补偿量仅 48%，KF 效果差于无预测 | 动态计算 `n_steps = round(T / dt)` |
| P4 | 延时信息未传入 obs | 控制程序无法自适应感知延时 | 可在 obs 中增加 `latency_s` 字段（需改正式源码） |
