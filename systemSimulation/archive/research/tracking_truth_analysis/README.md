# Tracking Truth Analysis

## 1. 目的

本目录用于开展“基础跟踪方法在 realistic 模式下的上帝视角验证分析”。

这部分工作与项目研究方向直接相关，但**不修改项目现有源码**，只做旁路研究与结果整理。

本专题重点回答三个问题：

1. 当前 `base` 跟踪方法是否真的表现为“云台比目标快一步”
2. 当前方法是否必须依赖保留一定误差，才能持续产生跟踪动作
3. 当误差较小时，当前方法是否会自然出现“继续贴紧目标的能力下降”

---

## 2. 边界

本目录下允许：

- 新增研究脚本
- 新增分析图
- 新增研究数据
- 新增研究说明文档

本目录下不做：

- 不修改 `simulation/`
- 不修改 `entities/`
- 不修改 `runtime/`
- 不修改现有 `tools/` 正式工具
- 不改变当前项目控制逻辑

也就是说，本专题只做“读取现有系统行为 + 从旁验证 + 产出分析结论”。

---

## 3. 为什么要做这项分析

当前额外实验里，我们已经能画出：

- 目标角
- 云台角
- 跟踪误差

但现在有一个关键问题：

当前图里的“目标角”并不是系统内部真实角，而是由以下量反算得到：

- 同一拍图像里的目标位置
- 同一拍云台角

因此，这条“观测反算目标角”天然和云台角存在耦合。

如果仅凭这一组图来判断“云台是否真的超前”，结论可能会被画图口径影响。

所以本专题需要再引入一套**上帝视角真值对照**：

- 目标真实角
- 云台真实角
- 真实角误差

这样才能区分：

- 是控制本身真的出现了超前
- 还是图的定义方式让它看起来像超前

---

## 4. 核心分析思路

### 4.1 双视角并行

后续分析同时保留两套量：

1. 控制器视角
   - 观测反算目标角
   - 云台测量角
   - 观测误差

2. 上帝视角
   - 目标真实角
   - 云台真实角
   - 真实误差

### 4.2 保持控制条件不变

分析时控制程序仍按当前项目真实用法运行：

- `obs_mode = realistic`
- 基线控制仍是当前 `RatePTracker` / `Kp` 速率控制

也就是说：

- 控制器不能偷看真值
- 真值只用于事后分析

### 4.3 重点验证的问题

后续重点看以下关系是否成立：

1. 目标持续运动时，系统是否必须保留非零误差，才能维持云台转速
2. 真值误差是否和目标真实角速度有明显相关性
3. 误差接近零时，云台真实角速度是否会自然下降
4. “云台看起来快一步”的现象，在真值视角下是否仍然成立

---

## 5. 建议输出

后续研究建议至少输出以下内容：

### 5.1 基础对照图

1. 观测视角三曲线
   - 观测反算目标角
   - 云台测量角
   - 观测误差

2. 真值视角三曲线
   - 目标真实角
   - 云台真实角
   - 真值误差

### 5.2 诊断图

1. 真值误差 vs 目标真实角速度
2. 真值误差 vs 云台真实角速度
3. 观测误差 vs 真值误差

### 5.3 结论说明

每轮分析都应明确回答：

1. 当前方法有没有明显 bug
2. 当前方法的局限到底是“代码错误”还是“结构性限制”
3. 当前 `base` 是否更适合作为研究基线，而不是最终高性能方法

---

## 6. 当前阶段结论

在正式做真值对照前，当前已有的初步判断是：

1. 当前 `base` 方法未发现明显实现错误
2. 它更像“依赖误差来驱动角速度”的基础速率控制方法
3. 对运动目标来说，它天然可能保留一部分残余误差
4. 因此它适合作为基线，但未必适合作为最终高性能方法

这些判断需要通过本目录后续的上帝视角分析进一步验证。
