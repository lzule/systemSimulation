目前至少存在以下不完整项：

1. `YawDisplayConfig.default_mode` 没有进入基线冻结
2. `TrackerTuningConfig` 中的以下字段没有进入冻结：
   - `zoom_in_error_px`
   - `zoom_out_error_px`
   - `zoom_step_mm`
   - `zoom_cooldown_s`

统一补齐：

1. `baseline.py` 的 `BaselineConfig`
2. `validate_baseline()` 的字段比对表
3. `docs/阶段0-基线收口/研究基线配置.md` 的说明文字

目标是让“文档写冻结了哪些配置”和“代码真的在校验哪些配置”完全一致。

## 问题 5：阶段 0 的验证链还不够稳

### 现象

阶段 0 声称：

- `conda run -n simulation python baseline.py` 可用
- `conda run -n simulation python tools/run_baseline.py` 可用

但本次复核时，这两个命令都触发了 `conda run` 的编码异常。

### 说明

这不一定说明脚本逻辑有问题，更像是：

- 脚本输出中包含中文
- `conda run` 在当前终端环境下打印时触发编码问题

### 影响

- 从“实际复现阶段 0 验证步骤”的角度看，这条验证链还不够稳
- 后续别人按 CHANGELOG 重跑时，可能以为脚本坏了

### 建议

做两件事：

1. 查清是 `conda run` 的终端编码问题，还是脚本输出方式的问题
2. 给基线工具增加更稳的输出策略，例如：
   - 尽量减少特殊字符
   - 保证控制台输出兼容
   - 或在文档中明确推荐的运行方式
